# 🎓 Student Management System (Backend REST API)

[![Spring Boot Version](https://img.shields.io/badge/Spring%20Boot-4.0.6-brightgreen)](https://docs.spring.io/spring-boot/current/reference/html/)
[![Java Version](https://img.shields.io/badge/Java-17-orange)](https://docs.oracle.com/en/java/javase/17/)
[![Database](https://img.shields.io/badge/Database-PostgreSQL-blue)](https://www.postgresql.org/)
[![ORM](https://img.shields.io/badge/ORM-Hibernate%20%2F%20JPA-red)](https://hibernate.org/)
[![License](https://img.shields.io/badge/License-MIT-purple.svg)](LICENSE)

An enterprise-grade, high-performance RESTful backend service built with **Spring Boot 4.0.6** and **Java 17**. The application serves as a robust engine for managing an academic ecosystem, handling multi-tier relational mapping across Students, Courses, Professors, and Admissions with deep validation layers, data safety boundaries, and strict transactional consistency.

---

## 🗺️ System Architecture

The application implements a decoupled, **Layered (N-Tier) Architecture** to ensure clean separation of concerns and clear data boundaries:

[ Client Request ] (Postman / Frontend UI)
│
▼
┌───────────────────┐
│  REST Controller  │  --> Exposes API routes, parses JSON payloads & handles @Valid input constraints
└─────────┬─────────┘
│
▼
┌───────────────────┐
│   Service Layer   │  --> Orchestrates business workflows, data mapping (ModelMapper) & transactions
└─────────┬─────────┘
│
▼
┌───────────────────┐
│ Data Access Layer │  --> Relational mapping using Spring Data JPA Repositories
└─────────┬─────────┘
│
▼
┌───────────────────┐
│   PostgreSQL DB   │  --> Persistent data storage managing relational tables with integrity constraints
└───────────────────┘

## 🛠️ Tech Stack & Dependencies

* **Core Framework:** `Spring Boot 4.0.6` (Spring Web MVC)
* **Runtime Environment:** `Java 17` (LTS)
* **Persistence Layer:** `Spring Data JPA` backed natively by `Hibernate`
* **Database Engine:** `PostgreSQL` relational database
* **Data Validation:** `Jakarta Validation Starter` for server-side constraint checks
* **Object Mapping:** `ModelMapper 3.2.6` for smooth Entity-to-DTO data translation
* **Code Simplification:** `Project Lombok` (`@Getter`, `@Setter`, `@NoArgsConstructor`, `@AllArgsConstructor`, `@ToString`)

## 🗄️ Database Entity Schema Design

The persistence engine converts data models into highly structured relational tables with enforced constraints:

### 1. `student` Table
| Column Name | Data Type | Attributes / Constraints |
| :--- | :--- | :--- |
| `id` | `BIGINT` | `PRIMARY KEY`, `GENERATED BY DEFAULT AS IDENTITY` |
| `name` | `VARCHAR(255)` | `NOT NULL` |
| `email` | `VARCHAR(255)` | `NOT NULL`, Unique |
| `address` | `VARCHAR(255)` | `NOT NULL` |
| `phone` | `VARCHAR(20)` | `NOT NULL` |
| `gender` | `VARCHAR(20)` | `NOT NULL` |

### 2. `course` Table
| Column Name | Data Type | Attributes / Constraints |
| :--- | :--- | :--- |
| `id` | `BIGINT` | `PRIMARY KEY`, `GENERATED BY DEFAULT AS IDENTITY` |
| `code` | `VARCHAR(50)` | `NOT NULL`, Unique |
| `name` | `VARCHAR(255)` | `NOT NULL` |
| `description` | `TEXT` | Optional biographical description |
| `professor_id` | `BIGINT` | `FOREIGN KEY` references `professor(id)` `NOT NULL` |

### 3. `professor` Table
| Column Name | Data Type | Attributes / Constraints |
| :--- | :--- | :--- |
| `id` | `BIGINT` | `PRIMARY KEY`, `GENERATED BY DEFAULT AS IDENTITY` |
| `name` | `VARCHAR(255)` | `NOT NULL` |
| `email` | `VARCHAR(255)` | `NOT NULL`, Unique |
| `address` | `VARCHAR(255)` | `NOT NULL` |
| `phone` | `VARCHAR(20)` | `NOT NULL` |
| `gender` | `VARCHAR(20)` | `NOT NULL` |

### 4. `admission` Table
| Column Name | Data Type | Attributes / Constraints |
| :--- | :--- | :--- |
| `id` | `BIGINT` | `PRIMARY KEY`, `GENERATED BY DEFAULT AS IDENTITY` |
| `student_id` | `BIGINT` | `FOREIGN KEY` references `student(id)` `NOT NULL` |
| `admission_date`| `DATE` | `NOT NULL` (`YYYY-MM-DD`) |
| `fees` | `NUMERIC(10,2)`| `NOT NULL` |

⚙️ Local Setup & Installation
Step 1: Clone the Application Directory
Bash
git clone [https://github.com/YourUsername/StudentManagement.git](https://github.com/YourUsername/StudentManagement.git)
cd StudentManagement
Step 2: Configure Environment Connection Strings
Locate or create src/main/resources/application.properties and replace the parameters to match your local PostgreSQL database settings:

Properties
# Server Configuration
server.port=8080

# PostgreSQL JDBC Settings
spring.datasource.url=jdbc:postgresql://localhost:5432/student_management_db
spring.datasource.username=postgres
spring.datasource.password=your_secure_password
spring.datasource.driver-class-name=org.postgresql.Driver

# JPA/Hibernate Configurations
spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true
spring.jpa.properties.hibernate.dialect=org.hibernate.dialect.PostgreSQLDialect
Step 3: Build & Compile via Maven Wrapper
The distribution comes prepackaged with the Apache Maven Wrapper tool (mvnw), eliminating manual system environment configurations.

Linux / macOS / Bash Environments:

Bash
chmod +x mvnw
./mvnw clean package
Windows Environment (CMD / PowerShell):

PowerShell
.\mvnw.cmd clean package
Step 4: Launch the Microservice
Once the compilation phase passes and the .jar build finishes smoothly, deploy the local embedded Tomcat server:

Bash
./mvnw spring-boot:run
The application will boot up and listen for requests on: http://localhost:8080
